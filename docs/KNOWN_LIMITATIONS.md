# Known limitations

- Automated seller payouts, escrow, Stripe Connect, PayPal Multiparty, and seller money transmission are not included.
- Buyer refund/dispute cases now support buyer opening, seller replies, admin decisions, receipt/payout holds, and audited settlement evidence. The app does not issue Stripe or PayPal refunds: an administrator must process the refund with the provider and then match its verified webhook event. COD repayment happens outside the platform and requires an admin-recorded reference; the marketplace does not hold COD funds.
- Buyer support tickets, seller replies for linked seller orders, and admin triage/status/assignment are implemented with audit history, in-app alerts, and preference-controlled transactional SMTP emails for support/order events. SMTP provider settings can be managed in the admin dashboard, with deployment secrets retained as a fallback; verification expires after 24 hours and delivery is at-least-once and must be monitored. Provider adapters use SMTP credentials/endpoints rather than provider REST APIs. SMS, SLA timer/escalation policy, private staff notes, file attachments, and external helpdesk integration are not implemented. Store marketing remains a separate opt-in-only SMTP feature and still requires an unsubscribe signing secret and explicit deployment gate.
- Members & Security supports audited account suspension/reactivation and session revocation, but not account deletion, role changes/admin promotion, MFA management, or password resets. Suspended users must contact an administrator to restore access.
- Club Coins supports persisted account-email verification, admin-approved verified-purchase reviews, paid/receipt-confirmed purchases, and five-minute provider-backed live attendance. Awards are idempotent and audited; verified refunds reverse purchase and associated review awards. The server hard-disable remains on by default. The live streaming adapter is still unavailable, so live attendance cannot be earned until an owner configures and enables a healthy provider. Custom triggers, group targeting, expiring rules, redemption, conversion, and transfers remain unavailable.
- Webhooks & API status reports internal API/database availability, local verifier configuration, and the persisted inbound payment-event ledger. It does not call Stripe/PayPal for connectivity checks, confirm provider dashboard registration, or store HTTP delivery-attempt logs; external webhook delivery monitoring remains an operational/provider-dashboard task.
- PayPal Sandbox credentials and a registered, verified webhook are required for provider testing.
- The UI is a compact MVP shell; production branding, content, localization, image storage/CDN, and a full accessibility audit remain launch work.
- Product catalog image management remains separate from the CMS media pipeline; CMS uploads use local development storage only until production object storage/CDN is configured.
- Stock is reserved at order creation. A production policy is required for release after payment cancellation/failure.
- No tax engine, dynamic/external shipping rates, carrier APIs/labels/tracking, native apps, live video, bulk catalog migration, terminal hardware, or external inventory sync. Seller-entered shipping services and destination zones are available; they do not contact carriers.
- Live shopping supports seller draft/schedule management, approved product linking, admin session/report controls, and buyer product rails; these do not create a broadcast. A managed provider, publishing workflow, sandbox credentials, webhook/token integration, verified player/attendance, recording policy, chat, and advanced moderation remain unimplemented or owner-dependent. No simulated stream is used.
- CMS local media storage is development-only. Production object storage/CDN, malware scanning, image dimensions/video duration inspection, legal copy, and browser E2E remain owner/staging work.
