## Reproduced findings

- The repository has an established GitHub Actions CI workflow that runs Prisma generation/deployment on its disposable PostgreSQL service, lint, TypeScript checks, API tests, production builds, and Playwright. Separate container-security automation performs dependency/image checks and SBOM work. The email's claim that the project lacks CI tests or an npm audit gate is not accurate for this baseline.
- Both API and web ESLint flat-config files existed, but only selected the TypeScript parser; they defined no lint rules. ESLint therefore completed without meaningfully checking the source.
- The baseline includes structured JSON diagnostics with request correlation IDs in `apps/api/runtime/structured-logger.cjs`, surfaced through `apps/api/src/diagnostics.ts`. This is not a hosted error-monitoring or alerting service, so operational observability remains limited, but it is inaccurate to say that all structured logging is absent.
- Direct API runtime dependencies are declared in `apps/api/package.json`; the scanner's count of zero is a workspace/package attribution error. The API currently declares 19 runtime packages.
- At the `22627e4` release baseline, six optional/defaulted `config.ts` settings were missing from `.env.example`: `FX_REFERENCE_API_BASE_URL`, `FX_REFERENCE_MAX_AGE_HOURS`, `STORE_PLAN_BILLING_SANDBOX_ENABLED`, `STRIPE_STORE_BILLING_SECRET_KEY`, `STRIPE_STORE_BILLING_WEBHOOK_SECRET`, and `TRUST_PROXY_HOPS`. Subsequent merged configuration work documented them with safe defaults/placeholders. At `af7f538`, all 75 application-schema settings are represented; 19 optional integration settings are intentionally commented, and the required `DATABASE_URL` and `PASSWORD_PEPPER` entries are active. The separate Prisma CLI setting `PRISMA_MIGRATIONS_PATH` was not covered by the application schema and is added with a safe default and automated check in this PR. The email's approximate twenty-variable figure appears to mix runtime configuration with test/staging script variables; it is not a count of missing required runtime variables.
- Test harness variables are a separate category: `E2E_DATABASE_URL` and sandbox identities are generated per CI run; individual `WALLET_FUNDING_*_TEST_DATABASE_URL` values belong to guarded disposable-database regression scripts; `STAGING_TEST_MAILPIT_*` and `STAGING_TEST_CLAMAV_*` point only to local test services and default to loopback. They are not needed to boot the marketplace, so they are documented by their test/workflow contracts rather than given reusable database or service endpoints in `.env.example`.
- The assessment's large-file observations are reproducible at the release baseline: `apps/api/src/index.ts` has 1,267 physical lines, `apps/web/src/LiveShopping.tsx` 974, and `apps/web/src/Dashboard.tsx` 847. Rechecked at `af7f538`, the first and third files remain 1,267 and 847 lines; PR #42's product-dialog extraction reduced `LiveShopping.tsx` to 832. Focused PRs #44 and #45 extract seller-product UI and live-session API routes; they require current-head independent review before merge.
- The assessment's short history observation is consistent with the baseline's 39 commits, two authors, and no release tags. This is historical context, not a code defect to fix by manufacturing commits or tags.

## Lint and formatting baseline

The new ESLint presets currently produce no errors. To avoid mass-reformatting legacy application modules in a tooling-only change, Prettier checks all changed/new configuration and documentation files plus newly added source files; existing `apps/api/src` and `apps/web/src` files are incrementally exempt until they are refactored or intentionally formatted.

The first measured warning baseline is 37 API warnings (29 unused-symbol findings and 8 explicit `any` findings) and 102 web warnings (45 React hook dependency findings, 47 explicit `any` findings, and 10 unused-symbol findings). Workspace lint scripts ratchet those warning ceilings so newly introduced warnings fail CI. Open PR #47 removes verified unused/dead code and fixes an effect-loading issue, measuring 8 API / 91 web warnings on its branch; those results are not yet current-main metrics. Remaining warnings are visible, not resolved, and React Hooks rule-of-hooks violations and other recommended-rule errors remain fatal.

The first disposable-environment API coverage run passed 67 test files / 304 tests and measured 12.01% statements, 13.29% branches, 15.76% functions, and 13.25% lines. At `d6bae951` (immediately before the financial-boundary test PR), CI measured 14.32% statements, 15.02% branches, 18.24% functions, and 15.95% lines. After PR #43 merged, the successful post-merge CI artifact at `af7f538d` measured 15.37%, 15.80%, 19.32%, and 17.16%, respectively: gains of 1.05, 0.78, 1.08, and 1.21 percentage points against that immediate pre-PR baseline. The current API suite passes 76 test files / 365 tests. CI continues to enforce the conservative non-regression floors of 11%, 12%, 14%, and 12%; these remain a floor, not a claim of adequate coverage. PR #43 adds payment, commission, and wallet boundary tests. Authentication, subscription entitlements, seller isolation, upload scanning, and streaming authorization remain follow-up targets, with current E2E tests and PRs #44/#45 also providing separate regression coverage not counted by API unit-test coverage.

`npm audit --omit=dev` reports zero production dependency vulnerabilities. A full local `npm audit` reports ten moderate findings in the development lint-tool dependency chain (including ESLint/minimatch transitive advisories) and currently offers no compatible automatic fix. Do not apply a blanket major-version override without testing the lint toolchain; keep this visible for a dedicated dependency review.
