# Content CMS admin guide

## Roles and workflow

`ADMIN` and `CONTENT_EDITOR` can create and edit draft posts/pages. `ADMIN` is required to publish, unpublish, archive, restore revisions, change indexing controls, change navigation, and delete media. The role is enforced by API middleware; hiding a button is not authorization.

Typical workflow:

1. Create a draft with a lowercase unique slug and structured blocks.
2. Upload media and wait for the configured scan outcome. With the default `CONTENT_SCAN_REQUIRED=true`, uploaded files remain quarantined and cannot be published.
3. Create a short-lived preview URL. Preview URLs are single-use, expire after 10 minutes, and return `noindex,nofollow`.
4. An administrator reviews, optionally restores a prior revision, then publishes or schedules the item.
5. Published slug changes create a 301 redirect. Redirect chains and self-redirects are rejected.

Published content is available at `/blog/{slug}` or `/pages/{slug}` and through the corresponding `/api/content/...` routes. Only published, due content appears in public search, navigation, HTML, and `sitemap.xml`.

## Structured blocks

The API accepts headings, paragraphs, quotes, lists, images, videos with optional VTT captions, and downloadable files. Arbitrary HTML, scripts, iframes, raw JSON-LD, and unsafe URL protocols are rejected. JSON-LD is generated by the server from validated fields.

## SEO controls

Each item supports SEO title, description, canonical URL, Open Graph image, and noindex/nofollow flags. Defaults are derived from the title/excerpt. Metadata improves crawlability but does not guarantee ranking, indexing, or rich results; search engines control those outcomes.
