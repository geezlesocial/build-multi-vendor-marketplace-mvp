## Assumptions

- The target folder was empty and had no existing package manager or Git repository.
- The application uses PostgreSQL through Prisma and npm workspaces.
- Currency is a configured ISO currency (`CURRENCY`, default USD); all amounts are integer minor units.
- Delivery remains address-based with no tax engine or carrier integration. Seller-managed service/zone fees are described in `docs/SELLER_SHIPPING.md`; no external rate engine or shipping labels are included.
- Platform-owned products have no seller ID. Seller products require an approved seller and an enabled multi-vendor setting.

## Architecture

`apps/web` is a responsive React/Vite client. `apps/api` is an Express TypeScript API. Prisma owns the normalized PostgreSQL schema. Sessions are revocable, httpOnly cookies backed by hashed session tokens. Payment provider credentials are environment values only.

Existing plan versions and stores retain compatibility defaults, and activated plan versions remain immutable.

Store-scoped content APIs enforce ownership, quotas, revisions, publish states, media scan state, and audit records. Global CMS routes remain scoped to platform records. Seller media reservations use a Store lock and expire after one hour; direct object-storage uploads are short-lived and deployment-gated. Database media-reference guards preserve tenant scope and prevent public/private references from being reassigned or deleted. Because no malware scanner is provisioned, uploaded media remains quarantined and cannot be used in published content or public delivery. Browser editor drafts are optional local working copies, not durable backups.

Store Buster delivers only explainable organic recommendations based on first-party product/category signals and affirmative personalization consent. Opt-out clears stored signals; sellers see aggregate daily metrics only. Click metrics require one-use expiring impression tokens. Paid/sponsored placement has no delivery or billing implementation and remains disabled. Email plans currently provide plan limits and draft/list scaffolding only: there is no verified email provider, subscriber confirmation, or campaign delivery, and public signup fails closed. Store affiliate participation is plan-gated and reuses the existing platform affiliate ledger; it does not create seller commissions or seller payouts. Stores without a Store-specific participation record retain the legacy platform affiliate behavior.

## Proposed additive design and phase gates

1. **Dashboard stability (no schema change):** derive initial workspace/tab from URL, mirror navigation into history, handle back/forward, sequence fetches so stale responses cannot replace the current workspace, keep workspace panels mounted while switching to preserve drafts, and show retry/error states. Keep admin separate and keep seller authorization server-derived. Reproduce and cover the header/dashboard cart-count mismatch using server state.
2. **Currency catalog and reference rates (migration 28):** add a seeded ISO catalog with exponent/region and independent display, Store-pricing, checkout, subscription, and settlement/reporting capabilities (all new charge/subscription switches OFF). Add Store base currency and normalized Store display offers, immutable dated FX observations, and versioned manual overrides. USD remains the explicit default; existing currency columns are not rewritten. Use exact fixed-scale decimal/integer-rational arithmetic. Implement an injectable Frankfurter v2 adapter but do not make provider calls during development/tests; automatic availability requires an actual returned pair. Keep checkout charge currency at configured base because existing adapters only use it.
3. **Store/buyer currency behavior:** authorize Store currency settings from authenticated Store scope; only show offered display currencies with a usable fresh or effective manual rate. Keep display estimates distinct from charge totals. At quote and order transaction, reject mixed/unavailable product or shipping currencies and reject any charge currency that is not the current provider-supported configured base; never add unlike currencies or trust browser totals/rates. Snapshot any display estimate and exact rate on the order without changing charged minor-unit amounts.
4. **Location picker (migration 29 if kept separate):** persist optional validated latitude/longitude on a saved address only after the user explicitly selects and saves a pin. Use Leaflet with configurable tile URL, a visible OSM attribution and no address autocomplete/geocoding. Request browser location only after a button click. Keep text entry available and do not send coordinates to an external service. Tests block external tile traffic.
5. **Versioned seller commissions (migration 29):** add immutable, effective-dated policy versions targeting a Store or Store Plan version (Store override wins); snapshot the exact policy and merchandise-only base per seller order. Add an append-only, idempotent seller commission ledger; post only after provider-confirmed PAID or explicit COD collection after fulfillment. Add compensating entries for cancellations/refunds/disputes/chargebacks, with partial refund allocation based on explicit item allocations where available and safe review when a provider event lacks enough allocation detail. This is a policy ledger only: it does not alter seller payout balances, transfer funds, or perform deductions.
